【接口契约】

- `Snapshot`实现Clone+Send+Sync，持有 `Arc<DbInner>` 和拥有型Index Snapshot。
- Snapshot只通过 `ReadOptions.snapshot`选择读取视图，不增加重复get/iter/range公共方法。
- Snapshot必须校验所属Db；跨Db使用返回InvalidArgument。
- Healthy和WriteStopped允许创建Snapshot；Poisoned拒绝新Snapshot。
- 普通Iterator创建时取得隐式稳定Snapshot；显式Snapshot Iterator克隆拥有型视图。
- DbIterator初始Unpositioned，只有Valid时key/value同时为Some。
- SeekToFirst、SeekToLast和Seek可从Unpositioned或Exhausted重新定位；Failed不可恢复。
- `seek(&[])`定位最小Key；非空target最大60000字节。
- 每次定位或移动立即读取并完整验证当前ValuePointer和KV_RECORD，成功后才进入Valid。
- Iterator错误保存第一个StorageError、进入Failed、valid=false并由status暴露。
- 无效状态上的next/prev无副作用且不panic。
- 前后方向切换不得重复或跳过相邻Key。
- RangeCursor使用 `[start,end)`、流式前进和limit；创建成功时已经定位首项。
- None表示无界，Some(empty)表示最小边界；start>=end或limit=0返回正常空游标。
- Iterator和Range不取得写闸门、提交协调器或frontier mutex。
- Iterator/Range的当前Key和Value使用拥有型缓冲，移动后旧借用失效。

【禁止事项】

- 禁止Snapshot暴露Fjall类型。
- 禁止普通Iterator使用变化中的实时视图。
- 禁止Range预先收集全部结果到Vec。
- 禁止Cursor遇到损坏后跳过条目继续。
- 禁止Failed状态通过Seek恢复。
- 禁止Iterator/Range绕过RuntimeControl读取状态。
- 禁止引入Value Log GC或回收Snapshot可能引用的旧Record。

【测试要求】

- 跨Db Snapshot拒绝。

- Unpositioned、Valid、Exhausted、Failed全部状态。
- SeekToFirst/Last、lower-bound Seek、Next、Prev和方向切换。
- 空库、Seek越过首尾、无效状态next/prev。
- `[start,end)`、无界、空边界、start==end、start>end、limit=0和数量上限。
- Pointer、文件、CRC和Key损坏使Cursor/Range终止并暴露status。
- WriteStopped允许读取，Poisoned拒绝新读。

【接口契约】

- Db、Snapshot、Iterator、RangeCursor和operation guard均保持DbInner生命周期。
- Lifecycle分别跟踪外部可发起操作租约和已接纳operation guard。
- 最后外部租约释放时停止接纳、关闭写入口并撤销未started请求；started请求运行到协议终点。
- 最终资源释放等待全部operation guard，随后停止并回收后台任务，逆序释放组件并最后释放根LOCK。
- Drop不得隐式sync、恢复、清除首错或panic；关闭期间的新错误不得覆盖首错。
- cleanup只处理 `seq <= captured_durable_seq`，每轮从持久化Frontier捕获上界。
- cleanup单批最多1024个Metadata Key或1MiB编码Key；先删Mutation，最后删Meta；使用Buffer且不推进Frontier。
- RecoveryState存在时禁止普通cleanup；`seq > durable_seq` Descriptor禁止清理。
- cleanup失败不得改变既有事务结果；Fjall不可信错误进入RuntimeControl。
- Destroy使用与Open相同的根锁，不执行Recovery或Repair。
- Destroy前完整盘点并验证FORMAT/FORMAT.tmp、Identity、VLog身份和受管对象类型。
- 删除顺序必须是高到低VLog、vlog目录、index树、FORMAT.tmp、最后FORMAT；保留根目录、LOCK和非受管文件。
- index内部符号链接只删除链接本身，不跟随目录外。
- 第一次成功删除后失败必须 `partially_deleted=true`；修复后重试安全，不回滚已删除对象。
- Identity缺失、损坏、未知版本或与FORMAT错配时首次删除前失败。

【禁止事项】

- 禁止使用 `Arc::strong_count`作为并发关闭条件。
- 禁止后台worker形成DbInner强引用环。
- 禁止Drop执行sync=true屏障或在线恢复。
- 禁止cleanup删除未稳定Descriptor或修改User Index/Head/Frontier/Identity。
- 禁止Destroy跟随符号链接或删除非受管普通文件。
- 禁止Destroy失败时重建已删除对象进行回滚。
- 禁止FORMAT之前删除LOCK或根目录。

【测试要求】

- 最后外部租约停止接纳，started请求完成后才释放LOCK。
- Drop在Healthy/WriteStopped/Poisoned下不panic、不隐式sync。
- cleanup上界、批量预算、先Mutation后Meta和部分中断续跑。
- cleanup失败不改变原事务结果或Frontier。
- 打开中的数据库Destroy返回Busy。
- Destroy只删除受管对象，保留普通文件和LOCK。
- 受管符号链接不跟随。
- inventory、Identity、VLog删除、index删除、FORMAT.tmp、FORMAT和目录同步每阶段故障。
- partially_deleted准确，重试幂等。
- 两个数据库互换index目录时Destroy在首次删除前失败。
