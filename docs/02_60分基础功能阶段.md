【接口契约】

- 所有非空写请求必须经过WriteGate，按队列顺序取得唯一active资格，在锁外执行I/O。
- 同时需要frontier和写协调时，锁顺序固定为 `frontier_mutex -> WriteGate/CommitCoordinator`。
- 非空 `sync=false`：完整Envelope进入OS Buffer后，一个Fjall Buffer Batch原子写入User Index、Descriptor和HeadSeq；不修改DurableFrontier。
- 非空 `sync=true`：同步旧Frontier到事务末端涉及的全部VLog文件和目录项后，一个Fjall SyncAll Batch原子写入User Index、Descriptor、HeadSeq和完整DurableFrontier。
- Fjall Batch成功是线性化点；成功后不得执行能使本请求返回失败的持久化步骤。
- 空 `sync=false`只检查实例状态，不分配事务身份、不入队、不I/O。
- 空 `sync=true`必须按队列位置捕获S；S==D时无I/O成功，S>D时同步至end(S)并用一个只更新完整Frontier的SyncAll Batch推进。
- Frontier提交前必须重新检查当前D，禁止回退。
- 内存Head/Frontier、head_vlog_end和Stats只在Fjall Batch成功后更新。
- VLog或同步阶段失败且未进入Fjall commit时结果NotCommitted；是否停止写按第4.6节分类。
- 进入Fjall commit后结果无法确定时必须CommitUnknown+Poisoned+ReopenAndVerify。
- queued请求在状态迁移时NotCommitted；started请求必须完成真实协议终点。
- 60分阶段不启动Descriptor cleanup；不得伪装已实现，状态文档明确后移到阶段16。

【禁止事项】

- 禁止绕过WriteGate直接提交。
- 禁止group commit或合并不同公共请求。
- 禁止先发布User Index再用第二个Batch补Descriptor或Frontier。
- 禁止使用独立Index persist步骤。
- 禁止只同步当前事务而遗漏此前未稳定dirty files和新目录项。
- 禁止在CommitUnknown后自动重放请求。
- 禁止cleanup或Stats失败修改已经确定的Ok。
- 禁止在Gate锁内执行I/O。

【接口契约】

- 从D+1按序验证Envelope，首个无效事务停止推进C；后续事务不得越过。
- unstable文件缺失、断档、截断或Envelope损坏使当前事务不被接受，但在Descriptor完整时不直接当作stable corruption。
- 实际存在受管对象身份错配、类型非法或无法归属时必须fail closed。
- 精确计算published_end、accepted_end、needs_undo、needs_promote和needs_trim。
- 已有RecoveryState时验证字段与当前状态，并使用固定target，不重新计算C。
- 本阶段输出完全拥有型RecoveryPlan，不得保存Fjall Snapshot、Iterator、Keyspace、Backend或借用引用；不得执行commit、sync、truncate或delete。只有Plan成功生成后，后续阶段才允许在根锁持续持有时关闭零worker Backend并以正常worker重开。

【禁止事项】

- 禁止在Identity验证前解释其他Fjall状态。

【接口契约】

- needs_undo或needs_trim时，任何User Index或VLog修改前先用Fjall SyncAll持久化完整RecoveryState。
- Undo阶段必须满足 `head_seq == next_undo_seq`，按H到C+1逆序逐事务执行。
- 每次Undo前完整重新验证Descriptor，并验证当前User Index逐字节等于AfterState。
- 一个Undo SyncAll Batch必须同时恢复全部BeforeState、删除完整Descriptor、写 `head_seq=i-1` 和 `next_undo_seq=i-1`。
- 不得分Key提交Undo。
- Undo到C后同步旧E至accepted_end涉及的全部VLog文件和目录项。
- 一个SyncAll Batch同时写目标Head、完整DurableFrontier和下一Recovery phase。
- 只有目标Frontier成功持久化后才允许Trim。
- Trim按accepted_end截断边界文件、删除更高已证明后缀文件、同步文件和目录并重新盘点。
- accepted_end=Empty时删除全部已证明未提交VLog并恢复Empty append状态。
- Trim必须幂等；失败保留phase=Trim。
- Finalize只在字段关系满足时SyncAll删除RecoveryState。
- RecoveryState删除后验证 `head_seq==durable_seq` 且physical_tail等于durable end，再创建唯一AppendState。
- 执行Recovery前必须关闭阶段12的零worker Backend，以正常后台worker重开同一索引并立即再次验证DatabaseIdentity；全部Recovery commit使用该worker-enabled Backend，完成后同一Backend直接进入运行期，不得第三次重开。
- 任一恢复错误不发布公共Db，不使用写请求的NotCommitted/CommitUnknown。

【禁止事项】

- 禁止RecoveryState持久化前修改User Index或VLog物理尾。
- 禁止强行覆盖与AfterState不一致的User Index。
- 禁止先删除Descriptor再恢复BeforeState。
- 禁止目标Frontier持久化前truncate/delete。
- 禁止Trim已提交历史或不可达但已提交的旧Value记录。
- 禁止Recovery完成前开放Db、正常Writer、Descriptor cleanup或其他RustKV后台维护。只读分析和第二次Identity验证成功后，允许Fjall内部Flush/Compaction服务Recovery commit及解除反压，但不得改变Recovery协议或推进DurableFrontier。
- 禁止恢复代码修改DatabaseIdentity。

【测试要求】

- RecoveryState创建前、结果未知和成功后再次崩溃。
- 每个事务Undo提交前、结果未知和成功后再次崩溃。
- AfterState不匹配时fail closed且不覆盖。
- 多事务同Key必须严格逆序恢复。
- Frontier SyncAll前后再次崩溃。
- Trim边界truncate、逐文件删除、目录同步和尾部复核失败。
- Trim中途重复Open幂等继续。
- Finalize前后再次崩溃。
- 完整孤儿、残缺Record/PAGE_END和高编号文件不复活。
- 多次Open最终收敛为同一连续前缀和同一AppendState。
- 确定性制造4个sealed memtable或等价积压，使用子进程超时证明零worker Recovery commit会等待反压，而worker-enabled Backend能够完成相同Recovery。
- 第一次Identity或只读分析失败时不得创建worker-enabled Backend；第二次Identity失败时不得执行Recovery；时序测试证明执行Recovery与进入运行期的是同一个Backend。

【验收】

- `cargo build --locked`无error。
- `cargo test --locked --test recovery_execution --test recovery_recrash`全部通过。
- `cargo test --locked`全量测试全部通过。

【输出】
