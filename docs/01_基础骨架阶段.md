## 阶段2：持久化元数据与ValuePointer编码

【任务】一次性实现根FORMAT、事务Descriptor、系统元数据、RecoveryState和ValuePointer的最终v0逐字节编码、解码及严格校验。本阶段只实现纯数据与纯算法，不执行文件或Fjall I/O。

【接口契约】

- FORMAT v0固定36字节：`RUSTKV00`、版本0、16字节非零UUID、page size 65536、max key+value 60000，整数小端。
- `CommitSeq=u64`，0为空库哨兵；持久化Value小端，Transaction Metadata Key中的seq和ordinal大端。
- `TxUuid([u8;16])`全零非法。
- `VLogPos`固定12字节语义，offset允许到 `2^32`；空位置必须使用 `DurableVLogEnd::Empty`。
- TxMeta Key固定11字节，TxMutation Key固定19字节，并保持同事务有序连续。
- TxMeta v0固定86字节，字段、偏移和CRC覆盖范围与第5.4.2节一致。
- TxMutation必须编码User Key、BeforeState和AfterState，不得保存User Value；变长解码必须恰好消费全部输入。
- Descriptor CRC必须按 `RKDESC0 + TxMeta[0..82] + mutations` 的规范字节流计算。
- DatabaseIdentity v0固定32字节，Magic `RKDI`，CRC覆盖前28字节。
- HeadSeq固定8字节小端。
- DurableFrontier v0固定31字节，Magic `RKDF`，CRC覆盖前27字节，Empty和Position关系严格校验。
- RecoveryState v0固定49字节，Magic `RKRS`，CRC覆盖前45字节，phase和字段关系严格校验。
- ValuePointer v0固定16字节，字段顺序和宽度与第5.7节一致；解码必须在I/O前验证格式、file id、record length、value length和推导的key length。
- 未知版本返回 `IncompatibleFormat`；Magic、长度、CRC或关系错误返回 `Corruption`；写入参数错误返回 `InvalidArgument/CapacityExceeded`。
- 所有长度、偏移、计数和分配使用checked arithmetic与fallible allocation。

- 禁止序列化Rust内存结构或依赖结构体对齐。
- 禁止使用serde/bincode等未要求依赖。
- 禁止改变任一固定长度、Magic、字段顺序、大小端或CRC覆盖区间。
- 禁止在Transaction Metadata中保存User Value或分片。
- 禁止为Empty位置保留特殊file_id。

- 固定长度少1字节、多1字节拒绝。
- 每个Magic、版本、CRC、枚举和UUID损坏均有测试。
- Transaction Key按seq和ordinal正确排序。
- Descriptor缺失、额外、重复ordinal和重复User Key拒绝。
- Before/After四种状态组合均覆盖。
- ValuePointer最小/最大长度、页面头区域、记录中部和算术溢出纯校验。

## 阶段3：VLog物理格式与布局算法

【任务】实现Value Log最终v0物理记录格式、CRC、Envelope、页面布局规划、PAGE_END和文件滚动纯算法，不执行真实文件生命周期操作。

【读取章节】只读设计文档以下章节，其余章节本次不读：

- 第6.5节“文件滚动”
- 第9.1节“写入验证”
- 第10.2节“格式、边界与公共API测试”

【实现文件】

- `src/vlog/format.rs`
- `src/vlog/mod.rs`
- `tests/vlog_format_golden.rs`
- `tests/vlog_layout.rs`

【接口契约】

- PageHeader固定16字节，Magic `RKVP`，CRC覆盖前12字节。
- VLog FileHeader固定48字节，Magic `RKVLOG00`，CRC覆盖前44字节。
- RecordHeader固定39字节，Magic `RKVR`，版本0，类型 `0x01..=0x05`，Header CRC覆盖前35字节。
- `TX_BEGIN`固定71字节。
- `KV_RECORD`长度为 `55 + key_len + value_len`，最大60055字节。
- `DELETE_RECORD`长度为 `53 + key_len`。
- `TX_PREPARED_END`固定111字节，末8字节为 `end_record_len + RKTE`。
- `PAGE_END`长度必须为当前记录位置到页面末端，最小43字节，Padding全部为0。
- Record CRC和Footer CRC覆盖范围必须与第6.2.2节完全一致。
- Envelope CRC按 `RKENV0` 和第6.1.5节规范逻辑记录字节流增量计算，不包含物理Header、PAGE_END和物理CRC。
- `vlog_begin`包含事务为开始写入产生的PAGE_END、文件滚动和新文件头；`vlog_end`是Footer后的排他位置。
- 布局规划器逐条应用第6.5节六步规则，维持 `R==0 || R>=43`。
- 单条记录不得跨页面或文件；事务可以跨页、跨文件。
- 正向Envelope扫描和Footer反向定位必须验证身份、计数、op_index、CRC、物理边界及精确终点。
- 正式常量固定64KiB和4GiB；测试可通过crate私有几何参数模拟边界，但不得改变生产编码。

【禁止事项】

- 禁止定义裸全零PADDING记录。
- 禁止让PAGE_END进入Envelope CRC或逻辑操作计数。
- 禁止记录跨页或跨文件。
- 禁止在页尾留下1～42字节无法编码区域。
- 禁止使用物理分配块数代替逻辑文件长度。
- 禁止执行真实文件创建、写入、同步或Trim。

【测试要求】

- PageHeader、FileHeader、五种Record逐字节Golden Test。
- CRC32C标准检查值 `123456789 -> 0xE3069283`。
- 最大KV记录能放入第0页和后续页。
- 页尾剩余1、42、43字节三类布局。
- PAGE_END最小值、最大值、非零Padding、错误身份和错误CRC。
- Footer反向定位与正向扫描终点一致。
- op_index缺失、重复、乱序；BEGIN/Footer计数不一致。
- 单事务跨页和测试尺寸下跨文件。
- 记录恰好结束于页面边界或4GiB排他末端。
- 文件编号达到999999后拒绝继续滚动。
